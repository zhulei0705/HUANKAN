# 实时采集与SSE设计

主责 R09/R10/R11/R12/R25；审查 R16/R23/R26。

HTTP固定来源白名单，不接受用户自定义URL、不跟随跳转；HTTPS、无自定义端口、无用户身份段、无查询/fragment，4MiB响应上限，20秒响应超时/25秒总调用上限。统一客户端同步串行化，请求间至少500毫秒。5xx最多3次、退避2秒/4秒；429不立即重试，按Retry-After秒数/日期暂停该域名，至少60秒，无法解析时默认300秒。冷却状态当前只在内存，重启后丢失，需要后续持久化。

RSS解析禁用DTD与外部实体、约束官方域名、保留GUID、原文标题、链接、发布时间。允许官方缺发布时间，但只标待核验。FED使用ETag/Last-Modified；SEC CIK补齐10位，解析列数组与accessionNumber，生成官方档案链接，仅支持recent集合，历史文件与companyfacts尚未实现。

来源许可、启用状态、环境采集开关共同控制调度。许可到期阻断请求与持久化，任务日志记录真实HTTP状态、新增证据版本数、耗时与错误码。日志不打印密钥或原始内容。失败隔离区目前保存错误索引，尚未保留失败响应，因此不能保证重新解析恢复。进程退出遗留RUNNING任务的自动恢复尚未实现。

Outbox为持久化通知表，不删除已发送记录。SSE编号是Outbox id，事件名event，JSON含event_id、evidence_id、created_at；心跳是注释。客户端用带Authorization的fetch流读取，不把密钥放URL，重连发送Last-Event-ID。只有页面刷新查询成功后推进游标；暂停自动更新时保留通知计数。

服务每秒扫描当前连接，按序每次最多100条；最多50连接，5分钟超时客户端重连。这是实现配置，不是实际延迟指标。浏览器当前会话内游标用于去重和补读，刷新页面后重新从0补读，可造成历史更新通知重复，后续应提供快照游标协议。服务已发送不代表用户已读。

实际验收仍需：真实DB事务和重连补读、并行来源顺序、两个客户端、429/403/超时故障、背压、长期运行、真实新消息端到端时间。没有新消息时仅能报告历史采集与隔离推送测试，不能报告真实发布到页面延迟。
