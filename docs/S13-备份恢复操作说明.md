# 寰瞰备份恢复

执行 `./scripts/backup-restore-drill.ps1` 只备份正式huankan库，生成runtime/backups/UTC时间/huankan.dump、原始证据bin文件、逐份SHA-256清单和备份清单。ZIP原始批次、所有证据版本及引用在数据库完整备份内。备份需保存到独立受控介质；本机备份不等于异地备份。凭证从本地环境读取，不写入清单。

执行 `./scripts/backup-restore-drill.ps1 -RestoreDrill` 在已存在的独立55432实例创建全新huankan_restore_UUID数据库，恢复备份，并查询证据、ZIP哈希、金融事件/Outbox引用一致性。成功后保留恢复库供审阅。脚本拒绝将恢复目标设为5432或正式库，不重启任何PostgreSQL服务。

正式灾难恢复必须另行批准目标和停机窗口，先校验dump的SHA-256、证据清单和目标为空，再通过pg_restore --no-owner --no-privileges --exit-on-error恢复。验收后由操作者明确切换数据源。当前脚本没有自动覆盖、自动切库或自动删除历史备份功能。

备份文件与额外证据导出分别采用数据库一致性快照；持续采集期间两者可能包含不同数量的新记录，应核对时间与ID集合，不能仅比较实时业务库总数就判定备份丢失。本次实际演练数量及哈希见docs/evidence/s13-backup-restore.json。
