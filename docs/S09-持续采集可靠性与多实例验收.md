# S09 持续采集可靠性与多实例防护

CollectorGuard以独立PostgreSQL会话顾问锁互斥来源，附带UUID租约、2分钟有效期、10秒心跳。锁连接3分钟无心跳超时，自动恢复旧RUNNING任务。证据事务检查任务绑定的租约所有者并锁住租约，过期或失去所有权的任务不能继续写入。不同来源并行能力保留；不依赖Java进程内锁来保障多实例正确性。隔离两套Guard/不同真实数据库连接竞争、过期租约仍有会话锁时拒绝抢占、释放后恢复、失去所有权拒绝写入均已测试；未把这写成两个正式生产应用长时压力验收。

域名预算存PostgreSQL，跨实例2请求/秒、120请求/分钟；两个SEC域名共享同一预算，429冷却持久化。官方HTTP三次上限指数退避；GDELT持久任务失败至多8次自动尝试，超过需人工重新确认索引与错误后恢复，不宣称文件永久不存在。DNS、TLS、连接、超时、304、403、404、429、5xx、解析与完整性分开。没有HTTP响应的status保持NULL，304不产生新事件。

Windows DNS使用系统解析器；寰瞰后端单独优先IPv4。它们是稳定性调整，不把一次后续成功作为此前网络错误的确定根因证明。正文读取也有截止计时，防止ofInputStream只有响应头超时而正文永久阻塞。

本轮应用重启与全部证据清单核验：docs/evidence/persistence-restart.json；未修改系统开机服务。
